派对模式(Party Mode)是我最早写过的 BMAD 话题,当时只讲了"多个 agent 在一个房间里同时说话"——典型的入门级内容。今天补上迟到的作业:读了 `skills/bmad-party-mode/` 的 SKILL.md 和三份 references(`mode-auto.md`、`mode-subagent.md`、`party-memory.md`),才发现真正的工程全在我没写过的地方。这个 skill 的本质不是"让 agent 聊天",而是一份关于**独立性、生命周期和上下文路由**的编排契约。

## 四种模式,一个降级方向

session(一个心智在线给所有 persona 配音)、auto(混合)、subagent(每个 persona 背后一个真实 agent)、agent-team(常设团队,仅 Claude Code)。每种模式的文档都带着同一个逃生舱:如果你的 harness 不能生成 agent,就退回 session——"without comment",不解释。降级是设计好的默认路径,不是故障。

## 生成判定是 default-deny

`references/mode-auto.md` 是三份文件里最短的,规则也只有一条:auto 模式默认在线配音——闲聊、反应、"构成对话大部分的连接性来回"——只在**分歧本身就是这一轮价值**的时候才生成真正独立的 agent:

> 当这一轮的价值在于分歧的、未被着色的思考时,生成独立 agent:一次真正的评估、评审或批评——那种"如果一个心智给每一方配音、然后它们漂向一致"就会失败的评审。

裁决原则一行:"存疑时就自己配音——生成子 agent 是你要伸手去拿的例外,不是默认。"这是我在多 agent 框架里见过的最明确的反"什么都要并行"立场。

## 生命周期:idle, not done

`references/mode-subagent.md` 写了一条我从未见诸文字的生命周期规则。班底是**常设的**:每个 persona 一个 agent,轮次复用同一个句柄——"那份延续性正是让 persona 的宿怨、联盟和回环梗得以累积的东西。"然后是关键句:

> 一个交接完了你递给它的那件事的成员是 **idle,not done**——不要关闭、退休或解散它。满足开场意图不会结束派对;只有用户结束它,或者一次显式的 --non-interactive 收尾。

崩溃恢复也写明了:意外被关的,resume 它;resume 不动,如实说出来,然后**只重生那一个成员**。

## 上下文路由:一个共享的房间

整个交换每一轮路由给所有成员——用户的那一轮和每个其他 persona 的那一轮——即使没轮到它说话。"绝不只递给一个 persona 它要回答的那一片。跳过这步它们就漂得失步——穿着派对外衣的分开问诊。"这一句几乎是对"多 agent 系统常见做法"的直接否定:按需投喂上下文在评审场景是节流,在对话场景是断供。

## 约束边界:锁形式,放开推理

给子 agent 的简报约束两件事:长度上限(通常一到三句)和"对刚说的话做出反应,而不是交一份报告"。明确不约束的:怎么想。

> 约束长度和姿态保护对话;约束它们的推理杀死对话。

## 并行轮次之后的编织

并行跑一轮,意味着没有谁见过同一轮里其他人的话——原样输出就是"彼此并排作答,而不是彼此应答"。编排者的动作是重排(让反驳紧跟被反驳的话)、加连接语("等等 Winston,这反了"),但底线写死:"绝不改写一个 agent 论证过的内容——编织交付,保留实质。"

## 记忆:append-only 的 memlog

每个 party 一份 `{memory_dir}/{active}/.memlog.md`,append-only。入场不倒原始文件,而是让一个读者子 agent 返回"几百 token 的现在处于什么状态"的简报——蒸馏,不倾倒。纠错没有删除,只有追加一条覆盖条目,"房间读最新状态"。写入是静默的,房间永远不说"我记下了";写失败就静默跳过,"绝不让一次失败的写卡住派对"。

## 解释一切的设计基准

SKILL.md 里"Keep It Feeling Like a Party"一节是全 skill 的总纲,其中最反直觉的一条:"它们冲突,而你不解决它……不费力气达成的干净共识就是派对死亡的地方。"规格书字面上指示编排者**不要去调和**。把这条读进去,前面所有规则就都通了:default-deny 的生成判定保护分歧的价值,常设班底让分歧有历史可依附,全量路由让分歧基于同一份事实,锁形式不锁推理让分歧是真的分歧而不是排版差异。
