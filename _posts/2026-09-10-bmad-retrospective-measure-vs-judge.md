本文是[《证据契约》一篇（2026-09-03）]({% post_url 2026-09-03-bmad-retrospective-evidence-contract %})的续篇。上一篇讲的是 BMAD 复盘技能的**契约条款**；这一篇讲它的**架构脊梁**：把"测量"和"判断"拆成两层，以及测量层里那些防真实 bug 的工程细节。内容均已对照 `src/bmm-skills/ship/bmad-retrospective/` 当前源码逐条验证。

## 核心规则：没有指针的发现不算发现

SKILL.md 原文非常硬：每条发现都必须带来源引用（文件、行号、commit 或日志）；一个你指不出来的断言——一个编造的根因、一个 diff 里并不存在的模式——**不是发现，直接丢弃**。

怎么让 LLM 真的遵守这条规则？不是靠求它，而是把工作拆开。

## 确定性层：脚本只测量

`scripts/git_evidence.py`（约 200 行 Python）测量一切可测量的：每文件 churn、每故事 commit 归属、merge 计数。它的 docstring 写着：**"本脚本只测量——它永远不判断加速或违规。解释数字的是模型。"** LLM 从不数行数，它读 JSON 然后作解释。

## 防真实 bug 的工程细节

这一层最有价值的部分，是每条细节都在防御一个具体的失效模式：

- **argparse 失败也走 JSON-only stdout 契约。** 他们子类化 `ArgumentParser`（`add_help=False`）、覆写 `error()` 让它输出 JSON——并且干脆删掉了 `-h`，因为内置 help 会以退出码 0 打印用法文本，无声地破坏无人值守编排器依赖的契约。
- **两次 git 遍历，杜绝 merge 重复计数。** merge 对第一父的 diff 会**重述**第一遍已经数过的 churn，所以 merge churn 单独放进 `merge_files` 键，永不并入。`merges_measured` 与 `merge_count` 并排上报——两者的差值是一个**可见的声明**："有 merge 未被测量"，而不是一个无声的零。
- **`--no-renames`**：让重命名诚实地表现为一次删除+一次新增，而不是一个打不开的 `src/{a => b}` 伪路径把同一文件的 churn 劈到两个键里。
- **用 `surrogateescape` 解码，而不是 `replace`。** `replace` 会把每个非法字节映射成同一个 U+FFFD——两个不同的非 UTF-8 路径就坍缩成一个键，churn 被无声求和。仓库里这是一条 3 行的注释，却比我读过的大多数生产代码的错误处理都好。
- **严格的 `REV..REV` 校验**：裸的 `..` 会让 git 把一侧默认成 HEAD，`A...B` 是对称差——两者都会以退出码 0 测出错误的东西。
- **故事归属用词边界正则**（`\b1-2\b`），故事 1-2 才不会匹配上 11-2；二进制文件递增 `binary_revisions`，因为"未测量"不等于"零改动"；调用方传入的 `GIT_*` 环境变量一律剥除，泄露的 `GIT_DIR` 无法重定向测量。

## 判断层：模型只解释

LLM 只拿到第二阶段：任何单个 diff hunk 都显示不出来的聚合视图——上帝类的膨胀、重复度地图、规格与实现的对照——每条发现要么带出处链接，要么丢弃。子代理的发现被显式标注为"未验证的报告，不是既定事实"，路由之前必须回到一手来源复核。

## 裁决逻辑的三条硬规则

`references/acceptance-verdict.md` 里有三条值得任何验收流水线直接偷走：

1. 人类决策永远覆盖机器裁决。
2. epic 未达标且无人类决策时，记录为**未接受**——绝不无声地算作通过。
3. 任何未完成的故事把机器裁决强制为 **rejected**，即使在无人值守模式下。"未完成的交付不是关于已完成 epic 的开放性发现——epic 本身就不完整。"

跟进项同样处理：无法举证的项记为"未找到证据"，而不是"未做"——读者永远能分辨**查了且干净**与**根本没查**。

## 可迁移的模式

**LLM 复盘之所以编造根因，是因为它被允许自己铸造证据。** 确定性测量脚本是模型无法伪造的收据。用代码测量，用模型判断，并让每条判断引用一张收据。这对复盘有效；对任何"代理汇报自己工作"的流水线都有效。
