# BMAD 把 agent 文档当作必须反复自证的负债:project-context 理论深潜

这次钻的是 BMAD-METHOD 仓库里的 `docs/explanation/project-context-theory.md`——`bmad-project-context` skill(实现在 `src/bmm-skills/plan/bmad-project-context/SKILL.md`)背后的理论文档。它的出发点是一个不舒服的发现:**大多数写给 AI agent 看的文档会让 agent 变差。**

## 1. 实测基线:AGENTS.md 是负资产

仓库指令文件(AGENTS.md)在"有 vs 无"的对照测量里:**任务成功率没有提升,推理成本 +20%**。一项规模化研究里,**随机生成的规则打平了专家精心整理的规则**。

为什么会这样?看内容就知道:这些文件绝大多数在**复述仓库已有的东西**——目录结构、技术栈、架构摘要。研究测的是"可推导的书面上下文",而不是书面上下文本身。

## 2. 反例实验:隔离出真正的变量

针对训练数据里不存在的框架 API 跑了四组对照:

| 配置 | 通过率 |
|---|---|
| 无文档 | 53% |
| 可复用 skill,无提示 | 53% |
| 同一 skill + 明确指示去调用 | 79% |
| **AGENTS.md 里放压缩后的文档索引** | **100%** |

同样的文件格式,相反的内容——不是复述,而是**模型本来不知道的知识**。索引从 40KB 压到 8KB,性能无损。

## 3. 机制:条件检索不可靠

- 无提示的 skill 在 **56% 的情况下根本没被调用**;加明确指示后触发率 >95%,但通过率仍封顶 79%,且结果随措辞微妙变化摇摆。
- 一个 709 页 wiki 的消融实验里,agent **直接跳过索引**,根据问题去猜页面路径。

由此提炼的规则:**需要 agent 主动选择去取的索引会被跳过;已经在上下文里的索引不会。** 所以 BMAD 的每个 agent 都在 `module.yaml` 里自带:

```toml
persistent_facts = [
  "file:{project-root}/**/project-context.md"
]
```

`file:` 前缀触发路径/glob 解析,其余条目按字面作为事实加载。**永远加载 ⇒ 被迫极小。**

## 4. 准入测试:修剪测试(pruning test)

每一行都要过一个问题:**删掉这一行会改变 agent 行为吗?** 能进文件的:

- 多个命令看起来都对时,**哪个是对的**,加上纠偏说明(根测试脚本在本工作区什么都不做、集成测试要先起服务……)
- 代码表达不了的**策略**(冻结路径、生成文件、合规要求)——凭权威准入,不凭发现
- 只收**偏离生态默认值**的约定;默认就会做对的事实不配占一行
- 只收来自**实际观察到失败**的坑;吓人的扫描发现只能变成问题,不能变成条目
- **负面约束优于正面指导**(实测更好),且每条禁令必须指明允许的替代

## 5. 最反直觉的部分:退出规则反着走

一条策略只在两种情况下退役:**它守护的东西没了**(被移除或已机械强制),或**人手动让它退役**。"最近没出故障"永远不是理由。原文的表述极准:

> **一条生效的规则会抹掉自己的证据。** 这个文件的大部分价值,就是那些不再发生的失败。

所以审计(audit)的硬规则:**结束时文件只能变小或不变,永远不能变大**。刷新(refresh)会对每一行 diff 删除和重命名;当某个论断的来源消失时,论断要么对着新现实修正,要么删除——**绝不悄悄重新指向一个碰巧还提到它的文档**。

## 6. 两种高度,两种工件

- **实现上下文**(约束、命令、坑)是**代码仓库**的属性:小时级腐化、每次会话加载、必须极小——这是本 skill 管的。
- **规划上下文**(rationale、被否决的方案、归属、组织标准)是**项目**的属性:月级腐化、突发式查阅——另一个能力,单独交付。

试图用一个文件同时服务两者,正是催生前两代被替换 skill 的原因。

## 7. 被禁的文风

> "我们移除了 X,因为……"——被明令禁止的散文。**Git 拥有历史;文件只陈述当下为真的东西。**

一句话总结这套设计哲学:**旧 skill 写更多文档;这个 skill 维护更少的真相——更少、经过验证的,赢。**
